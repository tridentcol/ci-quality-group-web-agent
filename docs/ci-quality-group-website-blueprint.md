## 1. Project Overview

### Vision
Sitio público de **CI Quality Group** que vive en el **dominio raíz** (`<dominio>`), separado del panel del chatbot (`panel.<dominio>`). Es una página **muy gráfica, cinematográfica y diciente** —pero sencilla— con **video y foto reales** de la empresa y sus servicios (disposición final de desechos, chatarrización, compra/venta de chatarra). **Sin login.**

El objetivo número uno es **convertir al visitante en una conversación con el bot**: un CTA dominante lleva a **WhatsApp** con un mensaje pre-cargado que aterriza directamente en el asistente con IA. Además, la arquitectura queda **preparada para, en el futuro, incrustar un widget de chat web** que use el mismo cerebro del bot — sin necesidad de rehacer nada.

### Goals
- Transmitir escala, seriedad y responsabilidad ambiental con impacto visual (full-bleed media, movimiento en scroll).
- Conducir el tráfico a **WhatsApp → bot** con fricción cero (CTA omnipresente).
- Cargar rapidísimo pese al peso gráfico (Astro = HTML estático + media optimizada).
- **Estar lista para integrar el chat web del bot** más adelante (contrato + flag + componente ya cableados).
- SEO local sólido (que la empresa aparezca al buscar sus servicios en Colombia).

### Success Metrics
- % de visitantes que pulsan el CTA de WhatsApp (objetivo principal de conversión).
- LCP < 2,5s y Lighthouse > 90 pese al video/foto.
- Posicionamiento local (Google Business + JSON-LD LocalBusiness).
- Tiempo en página / scroll depth (engagement con el contenido gráfico).

|-------|-----------|-----|

### Spacing & Layout
- Escala base 4px; secciones generosas (padding vertical 96–160px) para sensación premium.
- Border radius: 16px tarjetas, full en botones/badges.
- Ancho máximo de contenido: 1280px; media a sangre (full-bleed) donde aporte impacto.
- Mobile-first (50%+ del tráfico será móvil): el video del hero usa `poster` y carga diferida en móvil.

### Component Style
Movimiento con propósito (parallax sutil, reveals al scroll, hover en tarjetas), nunca recargado. Overlays con degradado sobre el video para legibilidad. Transiciones 200–400ms con easing suave.

> Para el sistema visual y las secciones, usar `/ui-ux-pro-max` (paleta/tipografía) y `/frontend-design` (cada sección).

## 8. Integración con el Chatbot (preparada, NO obligatoria)

El objetivo: **hoy el CTA va a WhatsApp**, pero todo queda cableado para encender un **widget de chat web** que use el **mismo cerebro del bot** cuando se quiera, **sin refactorizar**.

### Qué se deja listo en ESTE proyecto (sitio web)
1. **Componente `chat/ChatWidget.tsx`** (island) ya creado pero **desactivado**.
2. **Feature flag** `PUBLIC_ENABLE_WEB_CHAT` (env). `false` → solo WhatsApp. `true` → además, el widget.
3. **`chat/chat-config.ts`**: lee `PUBLIC_CHATBOT_API_URL` y `PUBLIC_ENABLE_WEB_CHAT`. Define el contrato (abajo).
4. **Sin acoplamiento**: si el flag está `false`, el widget ni se importa ni se hidrata (cero coste, cero JS).

```ts
// src/components/chat/chat-config.ts
export const CHAT = {
  enabled: import.meta.env.PUBLIC_ENABLE_WEB_CHAT === 'true',
  apiUrl: import.meta.env.PUBLIC_CHATBOT_API_URL, // p.ej. https://panel.<dominio>/api/chat/web
}
```

### Contrato de la API (lo implementará el proyecto chatbot el día que se active)
```
POST {PUBLIC_CHATBOT_API_URL}        // p.ej. https://panel.<dominio>/api/chat/web
Body:  { sessionId: string, message: string }
Resp:  { reply: string, handoff?: boolean, quickReplies?: string[] }
```
- **Sesión anónima**: el widget genera un `sessionId` (UUID en `localStorage`), sin login.
- **CORS**: el endpoint del chatbot debe permitir `Origin: https://<dominio>`.
- **Mismo cerebro**: ese endpoint reutiliza el pipeline RAG existente registrando la conversación con `channel = 'web'` (el modelo del chatbot ya es agnóstico al canal — `conversations.channel` es texto libre).

### Addendum para el proyecto CHATBOT (cuando se quiera activar — no ahora)
Para encenderlo, el chatbot solo necesita añadir:
1. Ruta `app/api/chat/web/route.ts`: valida body (Zod), upsert de `conversations` con `channel='web'` y `external_id = sessionId`, corre el pipeline `generate()` existente, responde `{ reply, handoff, quickReplies }`. Habilitar CORS para el dominio raíz.
2. (Opcional) Rate limiting por `sessionId`/IP para el endpoint público.
> No requiere tocar el modelo de datos ni el motor: el canal `web` encaja en la arquitectura ya diseñada.

**Resultado:** activar el chat en la web el día de mañana = poner `PUBLIC_ENABLE_WEB_CHAT=true` + añadir esa ruta en el chatbot. Nada más.

## 9. Build Order

**Step 1 — Scaffolding**
```bash
pnpm create astro@latest ci-quality-group-website -- --template minimal --typescript strict
cd ci-quality-group-website
pnpm astro add tailwind react
pnpm add framer-motion gsap lucide-react
```
Configurar `.env.example` con `PUBLIC_WHATSAPP_NUMBER`, `PUBLIC_ENABLE_WEB_CHAT=false`, `PUBLIC_CHATBOT_API_URL`.

**Step 2 — Design system & tokens**
`styles/globals.css` con las custom properties (colores, fuentes auto-alojadas, escala de espaciado). Usar `/ui-ux-pro-max` para afinar paleta/tipografía.

**Step 3 — Layout base**
`BaseLayout.astro` (head, meta/OG, JSON-LD), `Header.astro`, `Footer.astro`, `WhatsAppFab.astro`. `lib/whatsapp.ts` con el deep link.

**Step 4 — Hero**
`Hero.astro` + `VideoBackground.tsx` (poster, lazy, fallback en móvil) + claim + CTA dominante. Es la sección que define el "wow".

**Step 5 — Servicios**
Content Collection `servicios` (3 archivos) + `Servicios.astro` con tarjetas gráficas y `Reveal.tsx`. Usar `/frontend-design`.

**Step 6 — Galería**
`Galeria.astro` + `Lightbox.tsx` con las fotos/videos reales optimizados (Astro `<Image>`, video con poster).

**Step 7 — Por qué / Proceso / Cobertura**
Secciones restantes con animación de scroll (GSAP ScrollTrigger). Mapa en Cobertura.

**Step 8 — CTA final + integración cableada (flag off)**
`CTAFinal.astro`. Crear `chat/ChatWidget.tsx` y `chat/chat-config.ts` **desactivados** (§8). Verificar que con el flag en `false` no se hidrata nada.

**Step 9 — Página de privacidad**
`privacidad.astro` (Ley 1581/2012). Enlace en el footer.

**Step 10 — SEO**
Metadata por página, OG image, `@astrojs/sitemap`, JSON-LD `LocalBusiness` (NAP de Colombia), `robots.txt`. Usar `/seo-audit`.

**Step 11 — Performance**
Lighthouse: optimizar imágenes (AVIF/WebP), `client:visible` en islands, precargar el poster del hero, comprimir videos. Objetivo > 90 y LCP < 2,5s.

**Step 12 — Deploy (Cloudflare Pages)**
Conectar repo a Cloudflare Pages, build `astro build`, asignar el **dominio raíz** (ya en Cloudflare), activar Cloudflare Web Analytics.
